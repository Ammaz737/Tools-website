# Shared provider spending limits

AI and plagiarism submissions reserve one unit from an Atlas collection before calling a provider. The cap applies globally across visitors and application instances, per UTC day. AI_DAILY_REQUEST_LIMIT defaults to 500; PLAGIARISM_DAILY_REQUEST_LIMIT defaults to 50. Both accept integers from 1 through 100000. These request caps are not currency budgets; per-request AI output is separately bounded.

One conditional MongoDB findOneAndUpdate increments the counter atomically. The built-in unique _id index prevents independent counters on upsert races; duplicate-key rejection denies the request. Writes require majority acknowledgement and a five-second operation timeout. TTL cleanup removes old buckets, while the UTC day in the key establishes reset independently of asynchronous deletion. Failed provider attempts still consume quota; there are no refunds that could race or allow repeated billable retries. Pending requests spanning midnight consume their reservation day.

Production requests fail closed with 503 if Atlas/quota storage is missing, fails or is misconfigured. Exhausted caps return 429 and Retry-After. Local development can run provider contract tests without storage; this exception does not apply to next start production mode. Existing per-minute process-local throttles remain an additional safeguard; deploy shared ingress protection for login, network and other public endpoints.

Tests cover atomic storage contract, concurrent callers, UTC reset, independent service caps, invalid configuration, outages and production-without-storage denial. These are deterministic contract tests, not a live Atlas concurrency or failover acceptance. User credentials are not configured.
